# 07 代码规范与迁移对照

## 1. 代码格式规范

### 1.1 类与方法的收尾空行（本项目强制）

**类的最后一个成员之后、类的结束大括号之前必须留一个空行**：

```java
public class User {

    private Long id;
    private String account;
    private Integer deleted;

}
```

**方法体内的最后一条语句之后、方法的结束大括号之前必须留一个空行**：

```java
public UserVO toVO(User user) {
    UserVO vo = new UserVO();
    vo.setId(user.getId());
    vo.setAccount(user.getAccount());

}
```

**最后一个方法之后、类的结束大括号之前同样要留空行**：

```java
public class VideoServiceImpl implements VideoService {

    @Override
    public VideoVO get(Long videoId) {
        Video video = videoMapper.selectById(videoId);
        if (video == null) {
            throw new BusinessException(ErrorCode.VIDEO_NOT_FOUND);
        }

        return toVO(video);

    }

    @Override
    public void delete(Long userId, Long videoId) {
        // ...

    }

}
```

**不要留连续两个空行**：一个空行的目的是视觉分隔，两个空行只会让文件变长。

### 1.2 缩进与换行

| 项 | 约定 |
| --- | --- |
| 缩进 | 4 个空格，不用 Tab |
| 行宽 | 建议 120 字符以内 |
| 大括号 | 左括号不换行（K&R 风格） |
| import | 不使用通配符 `import xxx.*` |

**import 顺序**（IDEA 默认，import 之间用空行分隔）：

```java
// 1. 项目内部
import io.github.gmjneko.gcfeed.common.api.ApiResponse;

// 2. 第三方
import org.springframework.web.bind.annotation.GetMapping;
import org.mybatis.spring.annotation.MapperScan;

// 3. JDK
import java.time.LocalDateTime;
import java.util.List;
```

## 2. 命名规范

### 2.1 类命名

| 类型 | 规则 | 示例 |
| --- | --- | --- |
| Controller | `{模块}Controller` | `VideoController` |
| Service 接口 | `{模块}Service` | `VideoService` |
| Service 实现 | `{模块}ServiceImpl` | `VideoServiceImpl` |
| Mapper | `{实体}Mapper` | `VideoMapper` |
| 实体 | 单数名词，与表名对应 | `Video`、`UserStat` |
| 请求对象 | `{动作}{实体}DTO` | `CreateVideoDTO`、`UpdateProfileDTO` |
| 响应对象 | `{实体}VO` 或 `{场景}VO` | `VideoVO`、`FeedItemVO` |
| 枚举 | 单数名词 | `FeedScene`、`ActionType` |
| 异常 | `{场景}Exception` | `BusinessException` |
| 配置类 | `{技术}Configuration` | `WebMvcConfiguration` |
| 常量类 | `{范围}Constant` | `CommonConstant`、`RedisKeyConstant` |

**VO 与 DTO 的区别**：

- `DTO`（Data Transfer Object）—— **入参**，从客户端接收数据。
- `VO`（View Object）—— **出参**，返回给客户端。

选这两个名字而不是 `Request` / `Response`，是 Java 圈的常见惯例。关键是**全项目统一**，不要混用 `XxxRequest` 和 `XxxDTO`。

### 2.2 方法命名

| 场景 | 前缀 | 示例 |
| --- | --- | --- |
| 查询单个 | `get` | `getVideo(Long videoId)` |
| 条件查询单个 | `find` | `findByAccount(String account)` |
| 查询列表 | `list` | `listTimelinePage(...)` |
| 分页查询 | `page` | `pageWorks(...)` |
| 统计 | `count` | `countUnread(Long userId)` |
| 新增 | `create` / `insert` | `createPublished(...)` |
| 更新 | `update` | `updateProfile(...)` |
| 删除 | `delete` / `remove` | `deleteVideo(...)` |
| 存在性判断 | `exists` | `existsAccount(...)` |
| 状态设置 | `set` | `setAction(...)` |
| 转换 | `to` + 目标类型 | `toVO(User user)` |

### 2.3 变量命名

| 类型 | 规则 | 示例 |
| --- | --- | --- |
| 普通变量 | 小驼峰，语义完整 | `videoId` 而不是 `vid` |
| 常量 | 全大写下划线 | `MAX_LIMIT` |
| 集合 | 复数形式 | `videoIds`、`items` |
| 布尔 | `is` / `has` / `should` 开头 | `isAuthor`、`hasMore` |
| 循环索引 | 用有意义的名称 | `for (Video video : videos)` 而不是 `for (int i = 0; ...)` |

**避免的命名**：

| 不好 | 原因 | 改成 |
| --- | --- | --- |
| `data` / `info` / `temp` | 无信息量 | `videoVO` / `userProfile` |
| `flag` | 不知道是什么标记 | `isPublished` |
| `list1` / `list2` | 无法区分 | `cardList` / `statMap` |
| `str` / `num` | 类型冗余 | `account` / `count` |

## 3. 注释规范

### 3.1 注释语言

**统一使用中文**。这是本项目的明确约定，便于团队阅读。

### 3.2 类注释

每个类都必须有类注释，说明**职责**：

```java
/**
 * 视频业务服务。
 *
 * <p>负责视频的发布、详情查询、作品列表与软删除。
 * 互动计数由 interaction 模块维护，本服务只读取展示。
 */
@Service
public class VideoServiceImpl implements VideoService {
```

**类注释应说明「这个类负责什么」，而不是「这是什么类」**：

| 不好的注释 | 好处 |
| --- | --- |
| `/** 视频服务 */` | 等于没写 |
| `/** 处理视频相关业务 */` | 太笼统 |
| `/** 负责视频发布、详情、作品列表与软删除；互动计数由 interaction 模块维护 */` | 说明了边界 |

### 3.3 方法注释

对外的 Service 方法必须有注释，说明业务规则与异常：

```java
/**
 * 发布视频，创建即上线。
 *
 * <p>同一 {@code Idempotency-Key} 重复提交时返回首次创建的视频，
 * 并靠 {@code uk_author_idempotency} 唯一索引保证并发安全。
 *
 * @param authorId       作者用户 ID
 * @param dto            发布参数
 * @param idempotencyKey 客户端幂等键，可为空
 * @return 视频详情
 * @throws BusinessException 参数非法时抛出，错误码见 {@link ErrorCode}
 */
VideoVO createPublished(Long authorId, CreateVideoDTO dto, String idempotencyKey);
```

**私有方法不必写完整的 Javadoc**，关键逻辑用单行注释说明「为什么」：

```java
// limit + 1 是分页技巧：多取一条即可判断后面还有没有数据，避免额外一次 COUNT 查询
int queryLimit = limit + 1;
```

### 3.4 注释的原则

**注释解释「为什么」，代码说明「是什么」**：

```java
// 不好：注释复述了代码
// 把用户 ID 赋值给 userId
Long userId = UserContext.requireUserId();

// 好：解释为什么这么做
// 拦截器在 afterCompletion 里清理 ThreadLocal，但异步任务可能在此之前启动，
// 所以这里提前把 userId 取出来传参，避免异步线程读到 null
Long userId = UserContext.requireUserId();
```

**过时的注释比没有注释更糟**。修改代码时必须同步更新注释。

## 4. 分层规范

### 4.1 Controller 层

**职责**：参数解析、参数校验、调用 Service、包装响应。

```java
@RestController
@RequestMapping("/api/videos")
@RequiredArgsConstructor
public class VideoController {

    private final VideoService videoService;

    /**
     * 发布视频。
     */
    @PostMapping
    @RequireAuth
    public ApiResponse<VideoVO> create(
            @Valid @RequestBody CreateVideoDTO dto,
            @RequestHeader(value = CommonConstant.IDEMPOTENCY_KEY_HEADER, required = false) String idempotencyKey) {
        Long userId = UserContext.requireUserId();

        return ApiResponse.success(videoService.createPublished(userId, dto, idempotencyKey));

    }

    /**
     * 查询视频详情，可匿名访问。
     */
    @GetMapping("/{videoId}")
    @OptionalAuth
    public ApiResponse<VideoVO> get(@PathVariable Long videoId) {
        return ApiResponse.success(videoService.get(videoId, UserContext.getUserId()));

    }

}
```

**禁止事项**

| 禁止 | 原因 |
| --- | --- |
| 写业务判断（`if (video.getStatus() == 2)`） | 业务规则应在 Service，Controller 只做协议转换 |
| 直接注入 Mapper | 绕过 Service 层的事务与缓存 |
| 加 `@Transactional` | 事务边界属于 Service 的职责 |
| try-catch 业务异常 | 全局异常处理器已覆盖 |
| 返回 `ResponseEntity` 包装 HTTP 细节 | 统一用 `ApiResponse`，状态码由异常处理器决定 |

**例外**：需要精确控制 HTTP 状态码的场景（如发布成功要返回 201 而不是 200），可以用 `@ResponseStatus` 或 `ResponseEntity`。但**状态码语义应该尽量由异常和统一约定决定**，不要在每个方法里手写。

**构造器注入**：用 `@RequiredArgsConstructor`（Lombok）或手写构造器，**不用 `@Autowired` 字段注入**。

| 方式 | 评价 |
| --- | --- |
| 字段注入 `@Autowired private XxxService` | ❌ 无法用构造器测试、循环依赖时静默失败 |
| 构造器注入 | ✅ 依赖明确、final 不可变、便于测试 |

### 4.2 Service 层

**职责**：业务规则、事务边界、跨模块编排、缓存读写。

```java
@Service
@RequiredArgsConstructor
public class VideoServiceImpl implements VideoService {

    private final VideoMapper videoMapper;
    private final VideoStatMapper videoStatMapper;
    private final FeedCacheService feedCacheService;

    @Override
    @Transactional(rollbackFor = Exception.class)
    public VideoVO createPublished(Long authorId, CreateVideoDTO dto, String idempotencyKey) {
        // 1. 业务规则校验（校验逻辑集中在这里，不散落在 Controller）
        String title = StringUtils.trimToEmpty(dto.getTitle());
        if (title.isEmpty()) {
            throw new BusinessException(ErrorCode.EMPTY_VIDEO_TITLE);
        }
        if (title.length() > CommonConstant.MAX_VIDEO_TITLE_LENGTH) {
            throw new BusinessException(ErrorCode.VIDEO_TITLE_TOO_LONG);
        }
        // ... 其余字段校验

        // 2. 持久化
        Video video = buildVideo(authorId, dto, title, idempotencyKey);
        try {
            videoMapper.insert(video);
        } catch (DuplicateKeyException ex) {
            // 幂等键冲突：回查已有视频返回
            return handleDuplicateIdempotency(authorId, idempotencyKey);
        }

        VideoStat stat = buildInitialStat(video.getId());
        videoStatMapper.insert(stat);

        // 3. 缓存处理（失败不影响主流程）
        warmUpCardCache(video);

        return toVO(video, stat);

    }

}
```

**事务注解的使用**

| 场景 | 注解 |
| --- | --- |
| 写操作（多表或需要原子性） | `@Transactional(rollbackFor = Exception.class)` |
| 只读查询 | `@Transactional(readOnly = true)` 或省略 |
| 单表写且无副作用 | 可省略（但显式声明更清晰） |

**`rollbackFor = Exception.class` 必须写**：Spring 默认只对 `RuntimeException` 回滚。如果方法内可能抛出受检异常（比如调用外部 HTTP 接口），不加这个参数会导致事务不回滚，产生脏数据。

**不要在事务内做耗时操作**：

```java
@Transactional
public void doSomething() {
    orderMapper.insert(order);
    httpClient.callExternalApi();   // ❌ 事务持有数据库连接，外部调用可能耗时数秒
    orderMapper.updateStatus(order);
}
```

正确的做法是把外部调用挪到事务外，或先提交事务再调用。

**事务内不要调异步方法**：`@Async` 方法在新线程执行，不参与当前事务，也读不到未提交的数据。

### 4.3 Mapper 层

**职责**：数据持久化，不写业务逻辑。

```java
@Mapper
public interface VideoMapper extends BaseMapper<Video> {

    /**
     * 按游标查询时间线页数据。
     *
     * <p>只返回排序所需的轻量字段，走 {@code idx_status_published} 覆盖索引。
     */
    List<FeedPageItem> listTimelinePage(@Param("cursor") TimelineCursor cursor,
                                        @Param("limit") int limit);

}
```

**约定**

| 项 | 约定 |
| --- | --- |
| 单表 CRUD | 用 `BaseMapper`，不写 SQL |
| 简单条件 | 用 `LambdaQueryWrapper` |
| 复杂查询 | XML（`resources/mapper/`）或 `@Select` |
| 参数 | 多参数必须用 `@Param` 标注 |
| 返回 | 复杂查询返回 VO 投影，不返回 Entity |

**XML 文件组织**：与 Mapper 接口同名的 XML，放在 `src/main/resources/mapper/` 下：

```text
resources/mapper/
├── VideoMapper.xml
├── InteractionMapper.xml
└── FeedMapper.xml
```

**`application.yaml` 需要配置**：

```yaml
mybatis-plus:
  mapper-locations: classpath*:/mapper/**/*.xml
```

## 5. 异常处理规范

### 5.1 抛异常

```java
// 用错误码的默认文案
throw new BusinessException(ErrorCode.VIDEO_NOT_FOUND);

// 需要更具体的信息
throw new BusinessException(ErrorCode.COMMENT_PERMISSION_DENIED, "只能删除自己的评论或自己视频下的评论");

// 包装底层异常，保留堆栈
throw new BusinessException(ErrorCode.SAVE_UPLOAD_FAILED, ex);
```

### 5.2 错误码选择

| 场景 | 错误码 |
| --- | --- |
| 参数格式错误 | `PARAM_ERROR` |
| 资源不存在 | 模块对应的 `XXX_NOT_FOUND` |
| 权限不足 | 模块对应的 `XXX_PERMISSION_DENIED` |
| 唯一性冲突 | 模块对应的 `XXX_ALREADY_EXISTS` |
| 依赖服务失败 | `INTERNAL_ERROR` 或模块的 `XXX_FAILED` |

### 5.3 不要捕获后不处理

```java
// ❌ 吞掉异常
try {
    doSomething();
} catch (Exception ex) {
    // 什么都不做
}

// ❌ 只打印不处理，调用方无法感知失败
try {
    doSomething();
} catch (Exception ex) {
    log.error("失败", ex);
}

// ✅ 要么处理，要么包装后抛出
try {
    doSomething();
} catch (BusinessException ex) {
    throw ex;                                        // 业务异常直接透传
} catch (Exception ex) {
    log.error("操作失败", ex);
    throw new BusinessException(ErrorCode.INTERNAL_ERROR, ex);   // 包装后抛出
}
```

### 5.4 「尽力而为」的操作要显式标注

有些操作失败不应该影响主流程（发通知、预热缓存）。这类地方必须：

1. 捕获异常。
2. 记 `warn` 日志（不是 `error`，因为它不影响主流程）。
3. 在代码注释里说明为什么吞掉。

```java
/**
 * 预热视频卡片缓存。
 *
 * <p>缓存预热失败不影响发布结果 —— 缓存未命中时会回源查询，只是首次访问略慢。
 * 因此这里吞掉异常，只记日志。
 */
private void warmUpCardCache(Video video) {
    try {
        feedCacheService.setCard(toFeedCard(video));
    } catch (Exception ex) {
        log.warn("视频卡片缓存预热失败 videoId={}", video.getId(), ex);
    }

}
```

## 6. 日志规范

### 6.1 级别选择

| 级别 | 使用场景 | 例子 |
| --- | --- | --- |
| `error` | 需要人工介入的故障 | 未预期异常、依赖服务不可用 |
| `warn` | 可预期的异常情况 | 业务异常、缓存预热失败、降级触发 |
| `info` | 重要的状态变更 | 应用启动、关键配置加载 |
| `debug` | 排查问题的细节 | 中间件解析失败的具体原因 |
| `trace` | 极详细的追踪 | 一般不使用 |

### 6.2 日志内容

**使用占位符，不要字符串拼接**：

```java
// ✅ 只有日志级别开启时才会格式化，省掉无用开销
log.warn("业务异常 uri={} code={} message={}", uri, code, message);

// ❌ 无论是否输出都要拼接字符串
log.warn("业务异常 uri=" + uri + " code=" + code);
```

**异常作为最后一个参数**：

```java
// ✅ SLF4J 会打印完整堆栈
log.error("查询视频失败 videoId={}", videoId, ex);

// ❌ 堆栈信息丢失（被当成普通参数）
log.error("查询视频失败 videoId={} ex={}", videoId, ex.getMessage());
```

**日志要带定位信息**：`videoId` / `userId` / `requestUri` 等，便于从日志反查问题。

### 6.3 不要打的日志

| 类型 | 原因 |
| --- | --- |
| 密码、令牌、密钥 | 安全风险，日志可能被采集分析 |
| 完整请求体（可能含敏感信息） | 同上 |
| 循环内的高频日志 | 刷爆磁盘，且淹没真正的信息 |
| 无信息量的日志（`log.info("开始")`） | 噪声 |

### 6.4 当前配置

```yaml
logging:
  level:
    root: info
    io.github.gmjneko.gcfeed: debug
```

**生产环境应把业务包调成 `info`**，`debug` 级别会输出大量中间件细节。

## 7. Go 到 Java 的映射对照

### 7.1 分层结构

| Go | Java | 说明 |
| --- | --- | --- |
| `internal/domain/{module}/entity.go` | `modules/{module}/entity/*.java` + Service 内的校验 | 领域规则集中在 Service |
| `internal/domain/{module}/errors.go` | `common/api/ErrorCode.java` | 集中管理，不用每个模块一个文件 |
| `internal/domain/{module}/repository.go` | `modules/{module}/mapper/*.java` | 接口层省略，直接用 MyBatis-Plus |
| `internal/application/{module}/service.go` | `modules/{module}/service/impl/*ServiceImpl.java` | 一一对应 |
| `internal/infra/persistence/{module}/model.go` | `modules/{module}/entity/*.java` | 合并为一层 |
| `internal/infra/persistence/{module}/gorm.go` | `modules/{module}/mapper/*.java`（XML 实现） | 一一对应 |
| `internal/interfaces/http/{module}/dto.go` | `modules/{module}/dto/*.java` + `vo/*.java` | 拆分入参与出参 |
| `internal/interfaces/http/{module}/handler.go` | `modules/{module}/controller/*Controller.java` | 一一对应 |
| `internal/interfaces/http/router/router.go` | 各 Controller 的 `@RequestMapping` | 路由分散到各 Controller |
| `internal/interfaces/http/middleware/` | `common/interceptor/` + 注解 | 改为注解驱动 |
| `internal/infra/jwt/` | `common/jwt/` | 一一对应 |
| `internal/infra/cache/` | `modules/*/service/` 内的缓存逻辑 | 缓存并入 Service |
| `internal/infra/config/` | `application.yaml` + `@ConfigurationProperties` | 配置外置 |
| `internal/infra/metrics/` | Micrometer `MeterRegistry` | 用 Boot 自带方案 |

### 7.2 语言特性对照

| Go | Java |
| --- | --- |
| `error` 返回值 | `BusinessException` 异常 |
| `errors.Is(err, ErrXxx)` | `catch (BusinessException ex)` + 查 `ex.getErrorCode()` |
| `context.Context` | 无直接对应；用户身份用 `UserContext`，超时用 Spring 的 `@Transactional(timeout=)` |
| `interface{}` | `Object` 或泛型 `<T>` |
| struct tag `json:"xxx"` | `@JsonProperty("xxx")` 或全局命名策略 |
| 指针 `*string` 表示可空 | 包装类型 `String` 表示可空 |
| `nil` | `null` |
| `sync.Mutex` | `synchronized` / `ReentrantLock` / Redisson 分布式锁 |
| `singleflight.Group` | Caffeine `Cache.get(key, loader)` |
| `time.Time` | `LocalDateTime` |
| goroutine + channel | `@Async` + 线程池 / `CompletableFuture` |
| defer | try-finally / `@Transactional` 自动回滚 |
| `make([]T, 0, n)` | `new ArrayList<>(n)` |

### 7.3 接口路径对照

**全部保持一致**，前端可以直接复用。唯一的差别是响应体加了 `ApiResponse` 包装（见 [08 前端适配方案](08-前端适配方案.md)）。

### 7.4 字段命名对照

**JSON 字段名全部保持 snake_case**（与 Go 版一致），Java 内部用 camelCase，靠 `@JsonProperty` 或全局命名策略转换。

**推荐用全局配置**，避免每个字段都加注解：

```yaml
spring:
  jackson:
    property-naming-strategy: SNAKE_CASE
```

但要注意：这会让**所有** JSON 输出都变成 snake_case，包括 VO 里的嵌套对象。这是期望行为（前端就是按 snake_case 消费的）。

**不推荐用全局配置的原因**：如果某个接口需要 camelCase（比如调第三方 API），全局配置会造成困扰。折中方案是全局配置 snake_case，个别需要 camelCase 的字段用 `@JsonProperty` 覆盖。

## 8. 与原项目的差异决策清单

以下每一条都是在重写时**主动做的改变**，不是翻译偏差。

| # | 项 | 原实现 | 本版本 | 决策理由 |
| --- | --- | --- | --- | --- |
| 1 | 响应体 | 成功返回裸对象，错误用 `error` 或 `message` 两个不同的字段名 | 统一 `{code, message, data}` | 前端只需一套解包逻辑 |
| 2 | 鉴权方式 | 路由组挂中间件 | 注解驱动 | 解决 `/api/users/me` 与 `/api/users/{id}` 同前缀不同鉴权 |
| 3 | 登出 | 返回 204，令牌仍可用 | Redis 黑名单吊销 `jti` | 登出应该真正失效令牌 |
| 4 | 内部接口鉴权 | 三个接口无鉴权 | 统一 `X-Internal-Token` | 原实现是安全缺口 |
| 5 | 令牌比较 | `String.equals`（若用 Java 实现） | `MessageDigest.isEqual` 常量时间 | 防时序攻击 |
| 6 | 事务边界 | 下沉到 Repository 的 `Transaction()` | 上移到 Service 的 `@Transactional` | 符合 Java 分层与 readOnly 优化 |
| 7 | 逻辑删除 | 无 `deleted` 列 | 所有表加 `deleted` | 与 MyBatis-Plus 全局配置对齐 |
| 8 | 计数递减 | 应用层 `clampCount` | SQL `GREATEST(x-1, 0)` | 并发安全 |
| 9 | 关系统计读取 | 三个子查询实时聚合 | 优先读冗余表 | 减少聚合开销 |
| 10 | 时间类型 | `time.Time` → RFC3339Nano | `LocalDateTime` → `yyyy-MM-dd HH:mm:ss` | Java 生态惯例 |
| 11 | 错误文案 | 英文（保留） | 英文（保持） | 前端已有中文兜底，错误码才是稳定接口 |
| 12 | 计数缓存分片 | 基数 + 16 分片 | P0 简化为单键 JSON | 当前规模不需要，避免过早优化 |
| 13 | 互动落库 | 同步 + 异步双路径 | P0 只做同步 | 异步的一致性补偿复杂度高于收益 |
| 14 | MQ 死信 | 无 DLX，无限 requeue | 设计有限重试 + 死信表 | 避免毒消息热循环 |
| 15 | ffmpeg 错误响应 | 携带 stderr | 只记日志，对外统一文案 | 避免泄露工具版本与路径 |
| 16 | 消息写入失败 | 完全静默 | 记 `warn` 日志 + 指标 | 原实现无法发现通知链路失效 |
| 17 | 未读数查询 | 无缓存，每次打 DB | 建议加 60s 缓存 | 前端每次路由切换都请求 |
| 18 | 推荐召回 | 无缓存 | 建议加短期缓存 | 每次请求都跑召回 SQL + 向量查询 |
| 19 | `review_task` 审核员列 | 文档提到但表结构缺失 | 补 `assignee_id` | 补全文档缺口 |
| 20 | 配置读取 | 三处分散（`playback_config`、`admin_config`、代码默认值） | 建议统一配置服务 | 便于统一管理默认值与缓存 |

## 9. 代码评审检查清单

提交前自查以下项：

**格式与规范**

- [ ] 类的最后一个成员后、结束大括号前有空行
- [ ] 方法体内最后一条语句后、结束大括号前有空行
- [ ] 没有连续两个空行
- [ ] 类和方法都有中文注释，注释解释「为什么」而非复述代码
- [ ] 命名符合第 2 节规范（无 `data` / `flag` / `temp` 这类命名）

**分层**

- [ ] Controller 没有业务判断，没有直接注入 Mapper
- [ ] `@Transactional` 只在 Service 层
- [ ] 多参数 Mapper 方法都用了 `@Param`
- [ ] 构造器注入（`@RequiredArgsConstructor`），不用字段注入

**正确性**

- [ ] 写操作的事务有 `rollbackFor = Exception.class`
- [ ] 计数递减用了 `GREATEST` 或等价的钳制
- [ ] 列表查询返回的是 `[]` 而不是 `null`
- [ ] 分页查询用了「多查一条」判断 `has_more`
- [ ] VO 没有暴露 `password` 等敏感字段
- [ ] 手写 SQL 里显式写了 `deleted = 0`（原生 SQL 不会自动追加逻辑删除条件）

**异常与日志**

- [ ] 没有吞掉异常的分支（或已注释说明为什么吞）
- [ ] 「尽力而为」的操作记了 `warn` 日志

- [ ] 日志包含定位信息（`videoId` / `userId` 等）

**性能**

- [ ] 批量查询，没有在循环里查数据库（N+1）
- [ ] 列表查询没有 `SELECT *`，用了字段投影
- [ ] 游标分页的 SQL 与索引列顺序对应（跑 `EXPLAIN` 确认无 `Using filesort`）
- [ ] 缓存键都设置了 TTL
