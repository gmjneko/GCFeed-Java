# 推荐模块实现

推荐已接入 GET `/api/feed-items?scene=recommend` 和 POST `/api/feed-queries`，并提供三个内部接口。前端推荐页使用 POST，分页与行为信号共用 request_id。复用现有表，无数据库迁移。热榜和播放由各自模块实现，不在本文范围。

## 查询与评分

`RecommendationService` 编排 Repository、画像缓存、排序器和快照存储；不直接依赖 Mapper。复杂 JOIN 放 recommendation Repository，观看样本和近期曝光放 exposure Repository，向量批量读取复用 embedding Repository，卡片装配复用 Feed 的作者、统计、关系和互动状态查询。

首次查询召回最多 500 条 `status=2` 且发布时间非空的视频，排除用户最近 7 天曝光，按 `likes*3 + comments*5 + favorites*4`、发布时间和 ID 倒序截取。评分公式与模块设计 §6.4 一致，热度使用 long，相似度保留负值。画像取最近 30 天最多 200 条 play/complete，按创建时间及 ID 倒序取样，权重加权平均后 L2 归一化；错误维度、非有限数、零范数及相互抵消的画像走冷启动。

每页先按冻结排名选择条目，再有限轮次打散作者。不保证跨页作者分散，单一作者时直接追加结束。Feed 按打散后顺序批量装配；并发下架导致卡片缺失时跳过，不返回空占位。

## Redis 快照与画像

- `recommend:snapshot:v1:{UUID}`：真实 JSON 字符串，默认 TTL 1800 秒，存储用户、归一化场景、模型、维度、评分时间和冻结候选。
- `recommend:profile:v1:{base64(model)}:{dimension}:{userId}`：默认 TTL 300 秒，空数组表示已计算的冷启动画像。

键名由 RedisKeyConstant 管理，StringCodec 配合项目 Jackson 3 显式序列化。缓存配置位于 `gcfeed.recommendation`，候选池最大 500；读取不续期。画像异常回源计算并记录原因，快照异常返回 500/70011，不降级为动态评分分页。登录 JWT 黑名单仍依赖 Redis，不因画像缓存允许回源而绕过认证。

游标是无 padding 的 URL-safe Base64 JSON：`version=1`、`snapshotId`、`offset`。有效位置必须为整数并在快照范围内。跨用户/场景或非法游标返回 400/70002，过期/丢失快照与模型空间变化返回 410/70013。

每页批量查询剩余候选的当前上线状态和最新曝光，过滤后继续取满页。偏移按打散前最后选中条目的位置推进，has_more 根据剩余有效候选判断；全被过滤时返回空数组、空游标及 false。热度、画像、时间和新视频变化只能影响新查询。

## 内部接口与事务

InternalTokenInterceptor 保护 `/internal/**`，令牌由 `gcfeed.internal.token` 配置，经 UTF-8 字节比较；不要求 JWT，不向前端提供内部令牌。三个接口共用 32/64 Unicode 字符清洗规则，scene 为自由字符串，user_id 必须为正。

曝光决策在最近 7 天窗口内跨场景判断，包含恰好落在边界的曝光；未知视频返回 fresh，空输入不查库。批量曝光按首次出现顺序去重，批量确认视频上线，按 ID 升序写入并恢复输入顺序返回。整个批次使用同一秒级时间和单个事务，复用公共上报的流水、原子 upsert 和回查。任何失败回滚全部流水和聚合，包括已有聚合更新。重复成功请求再次累加，不承诺请求幂等。

## 前端观看信号

观察由 FeedPage 持有，不绑定暂时挂载的预加载层。只观察实际激活的视频；React StrictMode 的清理/重新挂载复用观察，暂停、恢复、重渲染和循环不会重复曝光或终结事件。离开后重新进入可产生新观察。

watch_ms 累计实际播放片段，排除暂停、缓冲、跳转与后台隐藏时间。退出时播放过则发送 play+skip，尚未播放只发送 skip；首次完播发送 play+complete，二者 completed=true。原生 loop 改为结束后受控重播，后续循环不重复上报；跳到末尾不算首次完整播放。信号独立于尚未实现的播放 QoS 接口，失败不重试、不阻塞切换，离开使用 keepalive 尝试发送。

快照过期保留当前视频和已加载条目，停止自动加载，点击“刷新推荐”后才建立新请求；池耗尽提供“换一批”。画像缓存允许新增信号最多延迟 5 分钟生效。
