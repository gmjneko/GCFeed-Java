# 曝光模块实现

本轮实现 `POST /api/video-view-events`，接收登录用户的观看行为，写入 `video_view_events`，仅在 `exposed` 时同步维护 `exposures`。两张表已在生产 schema 中定义，无需新增数据库迁移。

后续 recommendation 已补齐 `/internal/exposures`、`/internal/exposure-decisions` 和内部令牌拦截器，见 [推荐模块实现](04-推荐模块实现.md)。批量写入与本模块共用清洗及持久化逻辑；不新增消息或播放配置。

## 接口与参数

Controller 使用 `@RequireAuth`，从 `UserContext` 取 token 身份。DTO 没有 `user_id`，即使请求体带有其他用户 ID，也不会用它写入行为。成功统一返回 HTTP 201 和 `ApiResponse`。

| 参数 | 处理 |
| --- | --- |
| `video_id` | 必须为正，视频存在且 `status = 2`，否则 404 |
| `scene` | `strip()` 后用 `Locale.ROOT` 转小写，非空，最多 32 个 Unicode 字符 |
| `request_id` | 去首尾空白，最多 64 个 Unicode 字符；缺失、NULL 或空白存 NULL，响应省略该字段 |
| `event_type` | 去首尾空白、固定 Locale 转小写，仅支持四种类型 |
| `watch_ms` | 缺失或 NULL 默认为 0，负数复用 `INVALID_WATCH_MS(60005)` |
| `completed` | 缺失或 NULL 默认为 false；`complete` 强制为 true，其他事件保留客户端值 |

归一化后再检查长度，采用项目现有的 `codePointCount`，与 MySQL utf8mb4 的字符长度语义对齐。`strip()` 可处理全角空格，不对全角字母做半角转换。Go 原实现使用字节长度，这里有意沿用 Java 版已有的字符长度约定。

scene 是行为来源的自由字符串，不复用 `FeedScene`。这样 `hot`、`recommend` 或新场景在 Feed 接口开放之前，也能作为观看信号落库。

响应包含 `event`，仅 `exposed` 包含 `exposure`。字段使用 snake_case，时间使用 `yyyy-MM-dd HH:mm:ss`；聚合不暴露内部 ID、创建时间和更新时间。

## 分层与事务

`modules/exposure` 按 Controller、DTO、Entity、Mapper、Repository、Service、VO 分层。持久化实体提供无参构造、getter/setter 和手写 Builder；Service 不直接依赖 Mapper 或 Wrapper。

`VideoRepository.existsPublished` 只查询视频是否上线，不加载详情或互动统计。视频事实仍归 video 模块，曝光 Mapper 不跨表查询视频。

Service 的 `recordViewEvent` 使用 `@Transactional(rollbackFor = Exception.class)`：

1. 清洗参数并校验视频。
2. 生成精确到秒的服务端时间，插入流水并回填自增 ID。
3. `play`、`complete`、`skip` 直接返回流水，不修改已有曝光聚合。
4. `exposed` 用流水时间执行聚合 upsert，再在事务内回查实际聚合。
5. 流水、聚合全部成功才提交；写入或回查失败全部回滚。

首次曝光的 `first_exposed_at`、`last_exposed_at` 与流水 `created_at` 共用同一个时间，避免分别调用时钟造成响应与存储差异。后续曝光只更新最近时间、最近场景和次数，不改首次时间。

数据访问异常包装为 `SAVE_VIEW_EVENT_FAILED(70012)`，HTTP 500，保留底层异常原因。参数及资源错误原样透传。流水影响行数为零、主键未回填、聚合未写入或回查为空，也不能返回成功。

## 聚合 SQL 与并发

单表插入和回查使用 MyBatis-Plus。聚合 upsert 手写注解 SQL，属于代码规范 §4.3 的数据库方言判据：`insertOrUpdate` 的先查后写无法保证并发原子自增。

依赖 `uk_user_video`，首次插入计数为 1，冲突时按现有计数加 1。MySQL 分支使用 `AS new ON DUPLICATE KEY UPDATE`，并以 `exposures.exposure_count + 1` 明确引用已有行；H2 分支使用 `VALUES(col)`，共用 embedding 已注册的 `databaseId`。暂不抽取公共 SQL 类。

原始 SQL 不依赖 MyBatis-Plus 的实体时间填充：聚合 `created_at` 使用数据库默认值，更新时显式刷新 `updated_at`。upsert 返回影响行数，重复更新可能为 2，不能拿它作为曝光次数；响应必须使用事务内的回查结果。

流水不加唯一键，不接入 `@Idempotent`，重复 `request_id` 或 `Idempotency-Key` 都记录新行为。聚合唯一键只保证每个用户与视频维度一行，每次曝光仍累加次数，不重放首次结果。

## 观看事件与后续接入

本轮不定义或发布观看事件。用户画像按设计文档 §6.4 从最近 30 天 `play` / `complete` 流水与视频向量联查加权得到，推荐模块已实现按需计算和 5 分钟缓存。

## 验证

`ExposureModuleTest` 使用 H2 MySQL 模式、真实 Mapper、Spring 事务和 MockMvc。Redis 仅替代 token 黑名单存储，曝光读写不依赖 Redis。

覆盖四种事件、默认值与字段省略、完播规则、登录及伪造身份、视频可见性、固定 Locale、全角空格、ASCII/中文/Emoji 长度边界、无幂等上报、重复曝光时间与次数，以及同维度和不同维度的并发累加。

失败注入覆盖聚合写入异常、回查异常或空结果、写入返回零、视频查询异常。回滚测试同时检查流水、新聚合及已有聚合的字段，避免只检查异常而漏掉部分提交。

测试 schema 对 H2 做两项适配：scene/request_id/last_scene 的存储长度扩展为 UTF-16 单元容量，业务仍限制 32/64 个字符；观看流水索引名加表前缀，避免 H2 schema 内索引重名。唯一约束和索引列组合与生产一致。

运行命令：

```bash
./mvnw -o -Dtest=ExposureModuleTest test
./mvnw -o test
```

2026-10-13 验证结果：新增 20 个曝光集成测试通过；全量 100 个测试通过，失败、错误及跳过均为 0。

真实 MySQL 的别名分支尚未进行数据库执行验证：本地未发现可用 MySQL 服务，Docker daemon 也未运行。H2 测试执行的是另一条方言分支，部署前应在真实 MySQL 测试环境验证首次写入、重复累加与回查。
