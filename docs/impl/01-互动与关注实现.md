# 互动与关注实现

本轮完成评论、关注关系和数据库关注流的后端与现有 console 前端闭环。RabbitMQ 不在本轮引入；需要异步分发、通知和热榜更新的位置保留 `TODO(RabbitMQ)`，后续应通过事务 Outbox 在提交后发布，并由消费者负责幂等、有限重试和死信处理。

## 后端

评论接口位于 `CommentController`：

- `POST /api/videos/{videoId}/comments` 创建评论，内容首尾空白会去除，长度按 Unicode code point 校验为 1～1000。
- `GET /api/videos/{videoId}/comments` 只读取已发布视频，使用时间加 ID 游标，默认 20 条，最多 100 条。
- `DELETE /api/comments/{commentId}` 允许评论作者、视频作者或管理员删除；评论软删除，视频作者可以删除已下线视频的评论。

评论记录和 `video_stat.comment_count` 在同一事务内更新。评论创建使用 Redis 短时重复提交保护，并由 `(user_id, idempotency_key)` 唯一索引完成持久化去重；窗口过后，同键同视频同内容返回已有评论，跨视频、内容不一致或原评论已删除返回 409。删除通过状态条件更新，重复删除不会重复扣减计数。

关系接口位于 `RelationController`：

- `PUT/DELETE /api/users/me/following/{targetUserId}` 关注或取关。
- `GET /api/users/me/following` 和 `GET /api/users/me/followers` 使用时间加对方用户 ID 游标分页。

关系和双方 `user_relation_stat` 记录在同一事务内更新。用户账号和统计记录按用户 ID 升序加锁，避免互相关注时反向加锁；只有状态变化才修改计数。列表只返回有效关系和未注销账号，并返回当前查看者是否关注列表用户的 `following` 字段。

`GET /api/feed-items?scene=following` 要求有效登录态，使用 `EXISTS` 直接筛选当前用户的有效关注关系和已发布视频，按 `published_at DESC, id DESC` 游标分页。新关注、取关和新发布视频会在下一次查询立即生效，不依赖收件箱回填。Feed 卡片同时返回 `following`。

## 前端

`console/src/useVideoComments.js` 管理评论抽屉的加载、分页、发表、删除、失败重试和请求键复用。评论数量使用服务端响应更新；视频、账号和场景切换时通过作用域与请求版本丢弃过期响应。

`console/src/App.jsx` 已接通关注/取关、个人页关注和粉丝列表分页、登录引导，以及关注流取关后的作者移除和补页。关注状态直接使用 Feed/关系接口返回的 `following`，不再全量拉取关注列表推算。

## 验证范围

- Maven：`./mvnw -o test`，H2 MySQL 模式下运行 67 个测试，包含评论权限、边界、游标、幂等冲突、事务回滚、并发关系计数和关注流鉴权/即时生效场景。
- 前端：`console/npm run build`，Vite 生产构建通过。
- H2 测试替身覆盖事务和 SQL 行为；真实 MySQL/Redis 的连接、索引执行计划和并发锁等待仍需在部署环境做一次接口联调。
